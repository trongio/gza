# T03 Gateway client and fixtures: implementation plan

Branch: `task/T03-gateway-client` (from `main` with T01 and T02). Every endpoint was
checked live with curl on **2026-09-28 between 20:43 and 20:49 Tbilisi time** (status,
content type, shape; the key was never printed). New facts are already in
`docs/TTC_API.md` (sections "Board caveat", "Schedule", "Positions", "Route detail",
"Stops of patterns", "Polylines", "Planner", "Geocoding", "Errors and encoding") and
ship with this plan. Versions checked the same day on Maven Central.

## 1. Goal

Give the app a typed, lenient client for every TTC gateway endpoint it will use. `:core:ttc`
(pure JVM) gets a Retrofit service with suspend functions on the existing `@GatewayHttp`
OkHttp client (placeholder host `https://ttc-gateway.invalid/`, rewritten by
`GatewayAuthInterceptor`), `@Serializable` DTOs that never crash on unknown fields, nulls or
missing fields, and mappers into new domain types in `:core:model` (stops, routes, patterns,
polylines, board rows, vehicle positions, schedules, trip plans, geocode results, transport
kind, value-class ids, `java.time` in `Asia/Tbilisi`). The raw board minutes and
`arrivalDelay` stay in the domain as explicitly named **hints**, never as truth: T05 and T10
decide what to believe. A public `TtcGatewayClient` facade throws one sealed
`TtcGatewayException` type, which T04 maps into its repository results. `tools/record-fixtures.sh`
records real responses (key stripped) into `core/ttc/src/test/resources/fixtures/`,
including stop `1:970`, routes 301, 326, 551, 472 and the known-bad cases, and every
endpoint is proven by a unit test that parses a recorded fixture. `:app` gets a Hilt
binding for the client. No UI, no device work.

### 3.2 Domain types in `:core:model` (package `ge.hackerman.gza.core.model`)

Plain `data class` / `enum` / `@JvmInline value class`, no `android.*`, no serialization.
KDoc on every hint field says why it is not trusted.

**Ids.kt** (extend the existing file):
```kotlin
@JvmInline value class StopId(val value: String)     // exists
@JvmInline value class RouteId(val value: String)    // exists; add: val isMinibus get() = localId.startsWith("minibus", ignoreCase = true)
@JvmInline value class VehicleId(val value: String)  // feed-prefixed "1:981", same require as StopId
@JvmInline value class PatternSuffix(val value: String) // "0:01", "1:03": require matches ^\d+:\d+$
    // val directionId: Int get() = value.substringBefore(':').toInt()
```
Each gets `companion object { fun ofOrNull(raw: String?): X? }` that validates **without
throwing** (share one private `isFeedPrefixed(String)` with the existing `require`), so
mappers never need a try/catch.

**Geo.kt**: `data class LatLon(val lat: Double, val lon: Double)` (require finite, lat in
-90..90, lon in -180..180; `ofOrNull(lat: Double?, lon: Double?)`),
`data class BoundingBox(val minLon, val minLat, val maxLon, val maxLat)` with `contains(LatLon)`.
**Tbilisi.kt** (extend): `val TBILISI_BOUNDS = BoundingBox(44.6, 41.6, 45.0, 41.85)`
(verified to return geocode results; order `minLon,minLat,maxLon,maxLat`).

**TransportKind.kt**: `enum class TransportKind { BUS, MINIBUS, METRO, CABLE_CAR, UNKNOWN }`.
Same four kinds as T06's UI `TransitMode`, so a UI mapper is 1:1 later. Minibus is only
derivable from a route id (`1:minibusR...`), never from `mode`/`vehicleMode` (both say
`BUS`), see 3.6.

**Language.kt**: `enum class Language(val code: String) { KA("ka"), EN("en"), RU("ru") }`.

**RouteColor.kt**: `@JvmInline value class RouteColor(val rgb: Int)` (0xRRGGBB);
`ofHexOrNull("00B38B" | "ff505b" | "#00B38B")` case-insensitive, anything else null.

**Stop.kt**: `data class Stop(val id: StopId, val code: String?, val name: String, val location: LatLon, val kind: TransportKind)`.

**Route.kt**:
```kotlin
data class Route(val id: RouteId, val shortName: String, val longName: String?, val color: RouteColor?, val kind: TransportKind)
data class RouteDetail(val id: RouteId, val shortName: String, val color: RouteColor?, val kind: TransportKind,
                       val patterns: List<Pattern>, val defaultPattern: PatternSuffix?)
data class Pattern(val suffix: PatternSuffix, val directionId: Int?, val firstStop: StopRef?, val lastStop: StopRef?, val headsign: String?)
data class StopRef(val id: StopId, val name: String?)
/** Stops of one pattern in travel order (one request per pattern, see TTC_API.md). */
data class PatternStops(val routeId: RouteId, val pattern: PatternSuffix, val stops: List<Stop>)
```

**Board.kt**:
```kotlin
data class StopBoard(val stopId: StopId, val fetchedAt: Instant, val arrivals: List<BoardArrival>)
/** One row of TTC's arrivals board. A hint, never truth: at a terminus the realtime value counts
 *  buses pulling in, and reads 0 while a bus waits for its departure (PLAN.md 2.0). */
data class BoardArrival(
    val routeShortName: String,        // the board has no route id; join by shortName
    val pattern: PatternSuffix?,
    val headsign: String?,
    val color: RouteColor?,
    val kind: TransportKind,           // from vehicleMode only: a minibus shows as BUS here
    val realtime: Boolean,
    val realtimeMinutesHint: Int?,     // raw, can be 0 for a parked bus
    val scheduledMinutesHint: Int?,    // raw, can be -76 for a trip that never ran
)
```
`fetchedAt` is stamped by the client from the injected `Clock`: board minutes are relative
to it, and T10 needs the anchor.

**Position.kt**:
```kotlin
data class RoutePositions(val routeId: RouteId, val fetchedAt: Instant, val vehicles: List<VehiclePosition>)
data class VehiclePosition(val vehicleId: VehicleId, val pattern: PatternSuffix, val location: LatLon,
                           val headingDegrees: Double?, val nextStopId: StopId?)
```
Nulls are kept as-is (they are the layover signal for T05). No "parked" boolean here: that
rule (terminus distance, two polls) belongs to `:core:predict`.

**Schedule.kt**:
```kotlin
data class RouteSchedule(val routeId: RouteId, val pattern: PatternSuffix, val periods: List<ServicePeriod>)
data class ServicePeriod(val fromDay: DayOfWeek, val toDay: DayOfWeek, val serviceDates: Set<LocalDate>, val stops: List<ScheduledStop>)
data class ScheduledStop(val stopId: StopId, val name: String?, val position: Int, val times: List<ServiceMinute>)
/** Minutes after the service day's midnight. May be >= 1440: "24:05" is 00:05 the next calendar day. */
@JvmInline value class ServiceMinute(val minutes: Int) {
    fun atDate(serviceDate: LocalDate): ZonedDateTime = serviceDate.atStartOfDay(TBILISI_ZONE).plusMinutes(minutes.toLong())
    companion object { fun parseOrNull(raw: String): ServiceMinute? } // "H:mm" or "HH:mm", hours 0..47, minutes 0..59
}
```
Period selection (serviceDates first, weekday fallback, `toDay` before `fromDay` wrap) is
T05's job; T03 only parses faithfully.

**Polyline.kt**: `@JvmInline value class EncodedPolyline(val value: String) { fun decode(): List<LatLon> }`
(Google algorithm, precision 1e5, verified live; malformed input stops at the last whole
point instead of throwing), `data class RoutePolyline(val pattern: PatternSuffix, val encoded: EncodedPolyline, val color: RouteColor?)`.
Kept encoded in the domain because T04 stores it compactly; decoding is pure and cheap.

**Trip.kt**:
```kotlin
data class TripRequest(val from: LatLon, val to: LatLon, val time: TripTime = TripTime.LeaveNow,
                       val kinds: Set<TransportKind> = TRANSIT_KINDS, val optimize: TripOptimize = TripOptimize.QUICK)
sealed interface TripTime { data object LeaveNow : TripTime; data class DepartAt(val at: Instant) : TripTime; data class ArriveBy(val at: Instant) : TripTime }
enum class TripOptimize { QUICK, LESS_WALKING }
data class TripPlan(val from: Place, val to: Place, val itineraries: List<Itinerary>)
data class Place(val name: String?, val location: LatLon)       // gateway gives no stop id here
data class Itinerary(val start: Instant, val end: Instant, val duration: Duration, val walkTime: Duration,
                     val walkDistanceMeters: Double, val legs: List<Leg>)
sealed interface Leg { val from: Place; val to: Place; val start: Instant; val end: Instant
                       val distanceMeters: Double?; val duration: Duration?; val polyline: EncodedPolyline? }
data class WalkLeg(..., val steps: List<WalkStep>) : Leg
data class TransitLeg(..., val kind: TransportKind, val route: LegRoute?, val realtime: Boolean,
                      /** Raw, seconds, can be 3676 or -3631 on an on-time bus. Hint only (PLAN.md 1.2). */
                      val arrivalDelayHint: Duration?, val intermediateStops: List<Stop>) : Leg
data class LegRoute(val id: RouteId?, val shortName: String?, val longName: String?, val color: RouteColor?)
data class WalkStep(val relativeDirection: String?, val streetName: String?, val distanceMeters: Double?, val location: LatLon?)
```
`TripTime` carries an `Instant`; the client formats it in `TBILISI_ZONE` (reason: callers
cannot accidentally pass a device-zone local time).

**Geocode.kt**: `data class GeocodeResult(val name: String?, val location: LatLon, val street: String?,
val houseNumber: String?, val locality: String?, val district: String?, val city: String?,
val postcode: String?, val osmId: Long?, val osmKey: String?, val osmValue: String?, val type: String?, val extent: BoundingBox?)`.

### 3.4 Public client

```kotlin
interface TtcGatewayClient {
    suspend fun stops(language: Language): List<Stop>
    suspend fun stop(id: StopId, language: Language): Stop
    suspend fun stopRoutes(id: StopId, language: Language): List<Route>
    suspend fun arrivalBoard(id: StopId, language: Language): StopBoard
    suspend fun routes(language: Language): List<Route>                       // modes=BUS,SUBWAY,GONDOLA
    suspend fun route(id: RouteId, language: Language): RouteDetail
    suspend fun schedule(id: RouteId, pattern: PatternSuffix, language: Language): RouteSchedule
    suspend fun patternStops(id: RouteId, pattern: PatternSuffix, language: Language): PatternStops
    suspend fun polylines(id: RouteId, patterns: List<PatternSuffix>): List<RoutePolyline>
    suspend fun positions(id: RouteId, patterns: List<PatternSuffix>): RoutePositions
    suspend fun plan(request: TripRequest, language: Language): TripPlan
    suspend fun geocode(query: String, language: Language, bounds: BoundingBox = TBILISI_BOUNDS): List<GeocodeResult>
    suspend fun reverseGeocode(at: LatLon, language: Language): List<GeocodeResult>
}
```
Decisions:
- **`patternStops` takes one pattern.** Live check: several suffixes in one call return a
  merged, de-duplicated list with no per-pattern order. One call per pattern is the only
  way to get travel order. The service still accepts a comma list (for the `-both`
  fixture documenting the quirk), but the public API cannot misuse it.
- `polylines`/`positions` accept several patterns (their responses are keyed by suffix).
  Empty `patterns` list: throw `IllegalArgumentException` before any request (the gateway
  would 400).
- `stop()` returns non-null: the gateway answers an unknown id with `500`, which surfaces as
  `TtcGatewayException.Http(500)`. A 200 body without a valid id/location is `Malformed`.
- **Main safety:** Retrofit suspend functions `enqueue` on OkHttp's dispatcher, so the
  network, `GatewayAuthInterceptor`'s `runBlocking` and JSON decoding never run on the
  caller's thread. Mapping runs on the caller's thread and is cheap (2,753 stops or one
  80 KB schedule in a few ms), so no dispatcher is injected (nothing is hardcoded either).
  T04 calls it from its IO context anyway. `execute()` is never used.
- `Clock` is injected (the app's `Clock.system(TBILISI_ZONE)`), used only for `fetchedAt`.

### 3.5 Retrofit service

Built by the factory: `Retrofit.Builder().baseUrl(TtcGateway.PLACEHOLDER_BASE_URL).client(gatewayHttpClient)
.addConverterFactory(json.asConverterFactory("application/json".toMediaType())).validateEagerly(validateEagerly)`.
Relative paths **without a leading slash** (`api/v2/...`), exactly as T02 3.4 specified, so
`GatewayUrls.resolve` appends them to the configured base (`.../pis-gateway`).

```kotlin
internal interface TtcGatewayService {
    @GET("api/v2/stops") suspend fun stops(@Query("locale") locale: String): List<StopDto?>
    @GET("api/v2/stops/{stopId}") suspend fun stop(@Path("stopId") stopId: String, @Query("locale") locale: String): StopDto
    @GET("api/v2/stops/{stopId}/routes") suspend fun stopRoutes(@Path("stopId") stopId: String, @Query("locale") locale: String): List<RouteDto?>
    @GET("api/v2/stops/{stopId}/arrival-times") suspend fun arrivalTimes(@Path("stopId") stopId: String, @Query("locale") locale: String,
        @Query("ignoreScheduledArrivalTimes") ignoreScheduledArrivalTimes: Boolean = false): List<BoardArrivalDto?>
    @GET("api/v3/routes") suspend fun routes(@Query("modes") modes: String, @Query("locale") locale: String): List<RouteDto?>
    @GET("api/v3/routes/{routeId}") suspend fun route(@Path("routeId") routeId: String, @Query("locale") locale: String): RouteDetailDto
    @GET("api/v3/routes/{routeId}/schedule") suspend fun schedule(@Path("routeId") routeId: String,
        @Query("patternSuffix") patternSuffix: String, @Query("locale") locale: String): List<ServicePeriodDto?>
    @GET("api/v3/routes/{routeId}/stops-of-patterns") suspend fun stopsOfPatterns(@Path("routeId") routeId: String,
        @Query("patternSuffixes") patternSuffixes: String, @Query("locale") locale: String): List<PatternStopDto?>
    @GET("api/v3/routes/{routeId}/polylines") suspend fun polylines(@Path("routeId") routeId: String,
        @Query("patternSuffixes") patternSuffixes: String): Map<String, PolylineDto?>
    @GET("api/v3/routes/{routeId}/positions") suspend fun positions(@Path("routeId") routeId: String,
        @Query("patternSuffixes") patternSuffixes: String): Map<String, List<VehiclePositionDto?>?>
    @GET("api/v2/plan") suspend fun plan(@Query("fromPlace") fromPlace: String, @Query("toPlace") toPlace: String,
        @Query("departMode") departMode: String, @Query("date") date: String?, @Query("time") time: String?,
        @Query("modes") modes: String, @Query("optimize") optimize: String, @Query("locale") locale: String): PlanResponseDto
    @GET("api/v2/geocode") suspend fun geocode(@Query("query") query: String, @Query("locale") locale: String,
        @Query("bbox") bbox: String): FeatureCollectionDto
    @GET("api/v2/geocode/reverse") suspend fun reverseGeocode(@Query("lat") lat: String, @Query("lon") lon: String,
        @Query("locale") locale: String): FeatureCollectionDto
}
```
- Encoding: Retrofit leaves `:` in `@Path` values (`/api/v2/stops/1:970`) and OkHttp
  percent-encodes `:` and `,` in queries (`0%3A01%2C1%3A01`). Verified live that the
  gateway accepts both forms, so no `encoded = true`. Tests assert the decoded
  `queryParameter(...)` values and the exact encoded path.
- A `null` `@Query` (`date`, `time` for `leaveNow`) is omitted by Retrofit.
- `QueryFormat`: coordinates `String.format(Locale.ROOT, "%.6f", d)` (never the default
  locale: `ru` and `ka` devices would write a decimal comma); `place = "lat,lon"`;
  `bbox = "minLon,minLat,maxLon,maxLat"`; plan `modes` = `WALK` plus
  `SUBWAY` (METRO), `BUS` (BUS or MINIBUS), `GONDOLA` (CABLE_CAR) in that fixed order,
  UNKNOWN ignored; `departMode` = `leaveNow` / `departAt` / `arriveBy`; `date`/`time` =
  `at.atZone(TBILISI_ZONE)` as `yyyy-MM-dd` / `HH:mm`; `optimize` = `quick` / `lessWalking`;
  pattern lists joined with `,`.

### 3.6 DTOs and mapping rules

`TtcJson` (exists: `ignoreUnknownKeys`, `explicitNulls = false`, `coerceInputValues`) is
the only `Json` used. DTO rules:
- **Every property nullable with default `null`**, including ones never seen null. Lists
  are `List<XDto?>? = null` (null elements allowed), maps `Map<String, XDto?>? = null`.
  Reason: a new null anywhere must drop one item, never a whole response.
- Enum-like fields (`mode`, `vehicleMode`, `fromDay`, `departMode`, `relativeDirection`)
  are `String?`, never Kotlin enums, so a new value (`TRAM`) cannot fail decoding.
- Numbers: `lat`, `lon`, `heading`, `distance`, `walkDistance` are `Double?`; `duration`,
  `walkTime`, `arrivalDelay`, minutes, `position`, `directionId` are `Long?`/`Int?`;
  `osm_id` `Long?` (`@SerialName("osm_id")`).
- Plan `startTime`/`endTime` are `String?` parsed by the mapper with
  `OffsetDateTime.parse` (handles `.000+00:00` and `Z`); a bare number is treated as epoch
  milliseconds (OpenTripPlanner's other format) via a `JsonPrimitive?` field.
- Geocode `coordinates: List<Double?>? ` and `extent: List<Double?>?`.
- `ProblemDto(type, title, status, detail, instance)` for RFC 7807 errors.

DTO shapes (from live responses, TTC_API.md):
`StopDto(id, code, name, lat, lon, vehicleMode)`, `RouteDto(id, shortName, longName, color, mode)`,
`RouteDetailDto(id, shortName, longName, color, mode, patterns, defaultPatternSuffix)`,
`PatternDto(patternSuffix, directionId, firstStop: StopRefDto, lastStop: StopRefDto, headsign)`,
`BoardArrivalDto(shortName, color, headsign, patternSuffix, vehicleMode, realtime, realtimeArrivalMinutes, scheduledArrivalMinutes)`,
`ServicePeriodDto(fromDay, toDay, serviceDates: List<String?>?, stops: List<ScheduledStopDto?>?)`,
`ScheduledStopDto(id, name, position, arrivalTimes: String?)`,
`PatternStopDto(stop: StopDto?, patternSuffixes: List<String?>?)`,
`PolylineDto(color, encodedValue)`, `VehiclePositionDto(vehicleId, lat, lon, heading, nextStopId)`,
`PlanResponseDto(from: PlaceDto, to: PlaceDto, itineraries)`, `ItineraryDto(startTime, endTime, duration, walkTime, walkDistance, legs)`,
`LegDto(mode, from, to, startTime, endTime, realTime, arrivalDelay, distance, duration, route: LegRouteDto, intermediateStops: List<StopDto?>?, legPolyline: PolylineDto?, steps: List<StepDto?>?)`,
`StepDto(relativeDirection, distance, streetName, lat, lon)`,
`FeatureCollectionDto(type, features)`, `FeatureDto(type, geometry: GeometryDto, properties: GeocodePropertiesDto)`.

Mapping rules (one principle: **identity or position missing drops the item; display
fields fall back or stay null; raw hint values are copied unchanged**):

| Domain | Required (else item dropped) | Fallbacks |
|---|---|---|
| `Stop` | valid `StopId`, valid `LatLon` | `name` null or blank: `code`, else `id.localId`; `kind` from `vehicleMode` |
| `Route` | valid `RouteId` | `shortName` null: `id.localId`; `color` via `RouteColor.ofHexOrNull`; `kind` via `KindMapping` |
| `RouteDetail` | valid `RouteId` (else `Malformed`) | patterns without a valid suffix dropped; `defaultPattern` null if invalid |
| `BoardArrival` | non-blank `shortName` | `realtime` null: false; minutes copied raw (0, negatives, nulls all kept) |
| `VehiclePosition` | valid `VehicleId`, valid `LatLon`, map key a valid `PatternSuffix` (else the group is dropped) | `heading` and `nextStopId` copied (null stays null; an invalid next stop id becomes null) |
| `ServicePeriod` | `fromDay` and `toDay` parse as `DayOfWeek` (trimmed, upper-cased) | invalid `serviceDates` entries dropped one by one |
| `ScheduledStop` | valid `StopId` | `position` null: 1-based index; `arrivalTimes` null: empty; each token `ServiceMinute.parseOrNull`, bad tokens dropped, order kept |
| `PatternStops` | per `PatternStopDto`: valid stop (as `Stop`) | entries whose `patternSuffixes` do not contain the requested suffix are dropped (a single-pattern response always contains it) |
| `RoutePolyline` | valid suffix key, non-blank `encodedValue` | `color` null allowed |
| `Itinerary` | parseable `startTime`, `endTime`, every leg valid | `duration` null: end minus start; `walkTime` null: zero; `walkDistance` null: 0.0 |
| `Leg` | parseable times, `from`/`to` with valid `LatLon` | `mode` `WALK` (case-insensitive) gives `WalkLeg`, anything else `TransitLeg`; an itinerary with any invalid leg is dropped (a plan with a hole is worse than no plan) |
| `TransitLeg.kind` | | `KindMapping.fromMode(mode, route.id)`; `arrivalDelayHint = arrivalDelay?.let(Duration::ofSeconds)` raw, even 3676 or -3631 |
| `GeocodeResult` | `geometry.type` Point (or null) with 2 finite coordinates, **`[lon, lat]`** | `extent` of 4 numbers normalised with min/max into `BoundingBox`, else null |

`KindMapping.fromMode(mode: String?, routeId: RouteId?)`: `SUBWAY` METRO, `GONDOLA`
CABLE_CAR, `BUS` MINIBUS if `routeId?.isMinibus` else BUS, `null`/other UNKNOWN
(case-insensitive, trimmed). Stops and board rows pass `routeId = null`.

Top-level: `stop()` and `route()` bodies with an invalid id throw `Malformed`; list
endpoints return whatever survives (an empty list is valid). The mappers never throw; they
are total functions over DTOs, which `LenientParsingTest` proves.

### 3.7 Error model

Exceptions, not a result type, at this layer (reason: every T04 repository wraps calls in
its own `Result`/state anyway; a sealed result here would be unwrapped twice, and Retrofit
suspend functions already throw). T04 catches `TtcGatewayException` at the repository
boundary and falls back to Room.

```kotlin
sealed class TtcGatewayException(message: String, cause: Throwable?) : Exception(message, cause) {
    /** No usable key anywhere (GatewayConfigUnavailableException). Retry later; do not hammer. */
    class NoKey(cause: IOException) : TtcGatewayException("Gateway key unavailable", cause)
    /** Connection, DNS, timeout, cancelled-by-OkHttp, config fetch failure wrapped by the interceptor. */
    class Network(cause: IOException) : TtcGatewayException("Gateway unreachable: ${cause.javaClass.simpleName}", cause)
    /** Non-2xx. 500 with a text body can mean an unknown id (TTC_API.md). 401 here means the retry also failed. */
    class Http(val code: Int, val problem: GatewayProblem?) : TtcGatewayException("Gateway HTTP $code", null)
    /** 2xx body that is not the expected JSON shape, empty, or lacks the one required identity. */
    class Malformed(cause: Throwable?) : TtcGatewayException("Gateway response malformed", cause)
}
data class GatewayProblem(val title: String?, val detail: String?)
```
`RetrofitTtcGatewayClient` wraps every call in one private `inline fun <T> call(block: () -> T): T`:
- `CancellationException` rethrown untouched (checked first; never wrapped).
- `retrofit2.HttpException`: read `response()?.errorBody()` (Retrofit already buffers it; cap
  at 4 KiB), decode `ProblemDto` with `TtcJson` only if the content type contains `json`,
  swallow decode failure (problem = null). Close the body.
- `GatewayConfigUnavailableException` gives `NoKey`; any other `IOException` gives `Network`.
- `SerializationException` and `IllegalArgumentException` (kotlinx throws both) and
  `KotlinNullPointerException` (Retrofit, null body for a non-null type) give `Malformed`.
- Messages come only from the code, the class name, or `problem.title`/`detail` (safe,
  e.g. `Required parameter 'bbox' is not present.`); never a URL, header or response body.
  Name the caught types explicitly (detekt `TooGenericExceptionCaught`).
- Programming errors (empty pattern list) are `IllegalArgumentException` thrown **before**
  the `call { }` block, so they are not disguised as `Malformed`.

## 6. Risks / open questions

1. **Conflicts with T06 (parallel branch).** T03 does not touch `gradle/libs.versions.toml`,
   `settings.gradle.kts`, `app/build.gradle.kts` or `build-logic/`. Shared files:
   `docs/TTC_API.md` (T06 adds a "Transport kinds and route colours" block after the
   routes table; T03's edits avoid the routes table and the first lines of "Schedule", so
   git should merge both, but whoever merges second must re-read the file), and
   `docs/tasks/BACKLOG.md` (manager only). New `:app` code is in a new file
   (`GatewayApiModule.kt`). T06's `TransitMode` and T03's `TransportKind` are deliberately
   separate (designsystem does not depend on model); a mapping belongs in a feature module later.
2. **Stops of patterns order.** Only single-suffix calls are ordered. If a pattern ever
   visits the same stop twice (a loop), the list may contain it twice; keep duplicates
   (never `distinct()`), and T04 must key pattern stops by (pattern, sequence), not stop id.
3. **500 for unknown ids.** `Http(500)` can mean "no such stop" or a real outage. T04 must
   not delete cached data on a 500, and must not retry it in a tight loop.
4. **Board has no route id.** Join on `shortName` (plus `pattern`) through stop routes.
   Metro and cable car numbers restart at 1, but they never share a stop with buses so far.
5. **Minibus kind** is derivable only from a route id. Board rows and plan legs (`route.id`
   is null) report BUS for minibuses; T07/T14 should look the kind up from the cached route
   by short name.
6. **Documented 326 case vs the real timetable.** PLAN.md says the board read 0 at 17:11
   with the next departure 38 minutes away, TTC_API.md says 17:49. Today's weekday
   timetable for 326 at `1:970` has 17:13, 17:31, 17:49 (18-minute headway), so "38
   minutes" cannot be right for a weekday. The derived fixture uses 17:32 (next 17:49).
   Open question for the manager: correct PLAN.md 1 and 2.0 to "17 minutes", or confirm the
   original observation had a skipped trip.
7. **Time-dependent captures.** `terminus` may not hit when run; that is why the real 20:43
   capture is committed and the derived set exists. Fixture tests must never depend on
   today's date: freeze clocks at the sidecar `recordedAt`.
8. **Fixture size.** `stops/all-en.json` pretty-printed is about 450 KB, the 551 schedules
   about 110 KB each; total well under 3 MB. Do not add `stops/all-ka.json` in T03 (T08 can
   record it when it needs Georgian search data).
9. **Retrofit 3 on OkHttp 5.** Retrofit 3.0.0 declares OkHttp 4.12; the BOM forces 5.5.0,
   which is binary compatible. If a `NoSuchMethodError` shows up, check the dependency tree
   before anything else.
10. **`LenientParsingTest` size.** With arrays trimmed to 3, expect roughly a few thousand
    dynamic tests, a few seconds. If it is slow, trim the plan fixture to one itinerary.
11. **detekt.** Watch `LongParameterList` (DTO constructors are fine because of defaults;
    the Retrofit `plan` has 8 parameters: suppress locally with a why-comment, or pass
    `@QueryMap` built by `QueryFormat`, whichever reads better), `TooManyFunctions` on the
    service interface (suppress on that interface only: it mirrors the API),
    `TooGenericExceptionCaught` (catch named types only), `MagicNumber` (name 1e5, 4 KiB,
    120 m box constants).
12. **Secrets.** Never print, `cat` or `Read` `ttc.properties` or `BuildConfig`. The
    recorder reads the key into a 600 temp file only. `tools/check-no-secrets.sh` must pass
    after step 7. The planner verified the snapshot bodies do not contain the key.
13. **CI does not run shellcheck/shfmt.** Run them locally in step 6. Adding a CI step is a
    possible follow-up (touches `ci.yml`, not in scope).
