# T01 Project foundation: implementation plan

Branch: `task/T01-project-foundation`. Versions checked on **2026-09-28** against Maven
Central, Google Maven, the Gradle Plugin Portal and services.gradle.org.

## 1. Goal

Create the Gza Gradle project from nothing: a multi-module build with `build-logic/`
convention plugins and one version catalog on the latest stable toolchain (AGP 9.4.1,
Kotlin 2.4.20, Gradle 9.8.0), the quality gate (Spotless with ktlint, detekt, Android
lint, unit tests) wired so `./gradlew spotlessCheck detekt lint test assembleDebug` is
green locally and on GitHub Actions, and an installable app (`ge.hackerman.gza`) with Hilt,
a light/dark Material 3 theme and a placeholder screen, proven by JVM unit tests, a
Compose UI test, Roborazzi screenshots, an instrumented smoke test and a Maestro flow.
`ttc.properties` feeds `BuildConfig` when present and the build still succeeds when it is
missing; no secret ever enters the repository.

Decisions:
- **JUnit 6.1.3** is the current stable JUnit Jupiter (same `org.junit.jupiter.api`

  causes trouble, fall back to `5.14.4` (latest 5.x) by changing one catalog line.
- **Retrofit 3.0.0** is stable; it ships `converter-kotlinx-serialization` in the same
  group, so no third-party converter.
- **detekt 1.23.8**, not 2.0: detekt 2.0 is still `2.0.0-alpha.6`. 1.23.8 embeds Kotlin
  2.0.21, see the pin in 3.4.
- **Navigation 2.10.2** (type-safe `@Serializable` routes, as CLAUDE.md requires), not
  Navigation 3.
- Libraries for Room, WorkManager, DataStore, Retrofit, OkHttp, serialization and MapLibre
  go in the catalog now but are **not used** by any module in T01 (they land in T02 to
  T04 and T11). Unused catalog entries are never resolved, so step 2 verifies each
  coordinate with a `curl` HEAD on its `.pom` (script in step 2).
- No `kotlinx-datetime`, no Truth, no MockK: `java.time` and `kotlin.test` assertions
  are enough for now.

Shared configuration details the implementer must get right:
- **Kotlin version override.** AGP 9 carries its own KGP dependency. Declaring
  `org.jetbrains.kotlin.jvm` and `org.jetbrains.kotlin.plugin.compose` with
  `version.ref = "kotlin"` in the root `build.gradle.kts` (`apply false`) and depending
  on `kotlin-gradle-plugin:2.4.20` in `build-logic/convention` puts KGP 2.4.20 on the
  build classpath, and Gradle resolves to the higher version. Verify with
  `./gradlew :app:buildEnvironment | rg kotlin-gradle-plugin` that 2.4.20 is selected.
- **JVM target 17 everywhere** (Android compile options, Android built-in Kotlin, JVM
  modules). The build runs on JDK 21. Do **not** use `jvmToolchain(...)`, so CI and local
  never auto-provision a JDK. Reason: 17 bytecode is safe for D8 and for every consumer.
- **JUnit Platform for all host tests:** in `configureJUnitPlatform()`,
  `tasks.withType<Test>().configureEach { useJUnitPlatform() }` plus
  `testImplementation(platform(junit-bom))`, `testImplementation(junit-jupiter)`,
  `testRuntimeOnly(junit-platform-launcher)`. The launcher is mandatory on Gradle 9 (it no
  longer injects one). Android modules that run Robolectric add
  `testRuntimeOnly(junit-vintage-engine)` so JUnit 4 Robolectric tests run on the same
  platform (done by `gza.android.screenshot`). Instrumented tests stay JUnit 4 with
  `AndroidJUnitRunner`.
- **Detekt** (`configureDetekt()`, applied by every base convention):
  `buildUponDefaultConfig = true`, `config.setFrom(rootProject.file("config/detekt/detekt.yml"))`,
  `parallel = true`, `source.setFrom("src/main/kotlin", "src/test/kotlin", "src/androidTest/kotlin")`
  (explicit, because detekt 1.23 does not discover sources from AGP built-in Kotlin).
  Reports: html + sarif. **Pin detekt's Kotlin**, otherwise detekt crashes with
  "compiled with Kotlin 2.0.21 but is currently running with 2.4.20":
  ```kotlin
  configurations.matching { it.name == "detekt" }.configureEach {
      resolutionStrategy.eachDependency {
          if (requested.group == "org.jetbrains.kotlin") {
              useVersion(io.gitlab.arturbosch.detekt.getSupportedKotlinVersion())
          }
      }
  }
  ```
- **Lint** (`configureLint()`): `abortOnError = true`, `warningsAsErrors = true`,
  `checkDependencies = true` in `:app` only, `xmlReport = true`, `sarifReport = true`,
  `disable += setOf("GradleDependency", "NewerVersionAvailable", "AndroidGradlePluginVersion", "OldTargetApi")`.
  Reason: version-bump checks depend on the network and the calendar, so they would turn
  CI red without a code change; bumps are a deliberate task. No lint baseline file.
- **Configuration cache and build cache on** (`gradle.properties`). Read
  `ttc.properties` through `providers.fileContents(...)` so it is a tracked
  configuration input.

  with `val hasGatewayKey: Boolean get() = gatewayKey.isNotBlank()` and an overridden
  `toString()` that prints `gatewayBaseUrl`, `firebaseProjectId`, and `<redacted>` (or
  `<empty>` when blank) for `gatewayKey`, `firebaseApiKey`, `firebaseAppId`. Reason: data
  classes print every field, and a logged config would leak the key.

### 3.6 `ttc.properties` to `BuildConfig`

`TtcProperties.kt` in build-logic:
```kotlin
internal fun Project.readTtcProperties(): Map<String, String> {
    val file = rootProject.layout.projectDirectory.file("ttc.properties")
    val text = providers.fileContents(file).asText.orNull
    if (text == null) logger.warn("ttc.properties not found: building with an empty gateway key. Run ./tools/fetch-ttc-config.sh")
    val props = Properties().apply { text?.let { load(it.reader()) } }
    return props.stringPropertyNames().associateWith { props.getProperty(it).trim() }
}
```
`TtcBuildConfigConventionPlugin` adds, in `android.defaultConfig`:

| BuildConfig field | Property | Fallback when missing |
|---|---|---|
| `TTC_GATEWAY_BASE_URL` | `ttc.gatewayBaseUrl` | `https://transit.ttc.com.ge/pis-gateway` (same default as the fetch script) |
| `TTC_GATEWAY_KEY` | `ttc.gatewayKey` | `""` |
| `TTC_FIREBASE_API_KEY` | `ttc.firebaseApiKey` | `""` |
| `TTC_FIREBASE_PROJECT_ID` | `ttc.firebaseProjectId` | `""` |
| `TTC_FIREBASE_APP_ID` | `ttc.firebaseAppId` | `""` |

Each value is emitted as a Java string literal with `\` and `"` escaped
(`"\"" + v.replace("\\", "\\\\").replace("\"", "\\\"") + "\""`). The build never fails
because the file is missing; the app simply has no fallback key (T02 then relies on
Remote Config). The key ends up inside the APK, which PLAN 3.3 accepts; `*.apk` is
gitignored.

Never read `ttc.properties` with an editor tool or `cat` it: the Read permission on it is
denied for agents on purpose. Gradle and `tools/check-no-secrets.sh` read it without
printing.

## 6. Risks / open questions

1. **Built-in Kotlin plus a newer KGP.** If AGP 9.4.1 rejects or ignores KGP 2.4.20,
   check `./gradlew :app:buildEnvironment`. If a hard conflict appears, fall back to the
   KGP version AGP brings for Android modules and keep 2.4.20 for JVM modules only;
   report it rather than setting `android.builtInKotlin=false` (that option disappears in
   AGP 10).
2. **KSP 2.3.12 with built-in Kotlin and Hilt 2.60.1.** Should work (KSP min AGP is
   8.12). If Hilt codegen fails, check that `com.google.devtools.ksp` is applied before
   `com.google.dagger.hilt.android` in `HiltConventionPlugin`.
3. **detekt 1.23.8 on Kotlin 2.4 code.** Needs the Kotlin pin in 3.4. If detekt cannot
   parse some 2.4 syntax, avoid that syntax; do not move to the 2.0 alpha.
4. **compileSdk 37 naming.** The platform directory is `android-37.0`. If
   `compileSdk = 37` is not found, use the new DSL form `compileSdk { version = release(37) }`.
   CI downloads the platform on demand; if the runner cannot, add
   `android-actions/setup-android` with `platforms;android-37.0`.
5. **Robolectric SDK 37.** Each run without a warm cache downloads
   `android-all-instrumented:17-robolectric-15733970-i7` into `~/.m2`, which setup-gradle
   does not cache, so CI pays that download every time (acceptable; add an
   `actions/cache` on `~/.m2/repository/org/robolectric` if it gets slow). If SDK 37 misbehaves, set `sdk=36` in both `robolectric.properties` files
   and note it in the PR.
6. **Roborazzi goldens across machines.** Local Ubuntu 24.04 and the CI runner should
   render identically with native graphics; if CI diffs appear, inspect the uploaded
   `*_compare.png`, raise `changeThreshold` modestly, never delete the verify step.
   Open question for the manager: after merge, require the `CI / gate` check on `main`
   with branch protection (`gh api`), which the backlog implies but does not state.
7. **Configuration cache.** All chosen plugins support it. If one does not, turn it off
   in `gradle.properties` with a comment naming the plugin, rather than working around it.
8. **Lint `warningsAsErrors`.** Expect issues such as `MissingTranslation`,
   `MonochromeLauncherIcon`, `UnusedResources` and `Typos` in the ka file. Fix them in
   the resources; suppress only with a `tools:ignore` plus a comment saying why.
9. **Gradle 9.8.0 is four days old** (built 2026-09-24). If it shows a regression, use
   9.7.1 (also stable, satisfies AGP 9.4's 9.6.0 minimum) and say so in the PR.
10. **Secrets.** Never `cat`, `Read` or echo `ttc.properties`; never paste BuildConfig
    output; `ttc.properties` must stay untracked (`git check-ignore ttc.properties`).
    The generated `BuildConfig.java` contains the real key locally: it is under `build/`,
    which is ignored.
11. **Emulator image is 16 KB page size (API 37.1).** No native code in T01, so no
    impact now; MapLibre 13.x ships 16 KB aligned libraries for T11.
12. **Maestro `clearState`** wipes app data: emulator only, never the S22.
